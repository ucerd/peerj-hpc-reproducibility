# Do not confuse technical reproduction with independent design-framework evaluation

| Material | Supported conclusion | Not established |
|---|---|---|
| Public earlier PakSupercomputer paper | Research on heterogeneous HPC architecture has been publicly disseminated | Independent validation of the PeerJ university-design framework |
| Supplied 18-page COTS technical manuscript | Author-reported 20-node deployment specification and tabulated benchmark outcomes | Raw-log reproducibility, uncertainty distribution or external site validation |
| PeerJ S2 Python + synthetic CSV | Capacity sizing under disclosed assumptions is executable and arithmetically checked | Empirical validity of assumed demand, queuing or system effectiveness |
| S1 source-to-requirement inventory | Existing coding is inspectable; contextual literature support identified | Recoverable original database queries, independent extraction agreement or complete historical exclusion pool |
| CAID training and project documentation | Institutional teaching, research and innovation demand categories are real | Validated numerical GPU-hours, queue targets, causal impact |
| Partner-support statements | Author-described technical transfer/advisory scope | Documented third-party go-live acceptance or independently observed framework feasibility |

No S1/S2 file can be represented as a completed independently recruited expert panel or held-out institutional evaluation without actual new evidence.
